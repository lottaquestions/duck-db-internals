## 15-sorting.md

DuckDB changes:
- Sort merges now use a tracked scratch buffer (`SortMergeBuffer`,
  `BufferedMergePolicy`, new `buffered_merge.hpp`) instead of
  `std::inplace_merge`'s `operator new` buffer; sinks budget it via
  `SortedRun::SizeInBytesForSorting()`.
- Ska Sort: buckets < 128 rows go straight to pdqsort; `StdSortFallback`
  (vergesort + pdqsort) now only for equal-leading-key buckets and takes the
  merge policy.
- `ORDER BY` no longer turns `-0.0` into `0.0` (FLOAT/DOUBLE key columns
  routed through the payload).
- `HashedSort` partitions directly on a bounded single integer key
  (`IntegerPartitionedTupleData`, cap 256 values) — no hashing or sorting for
  `PARTITION BY` / partitioned `COPY` without `ORDER BY`.
- `PhysicalTopN`: threads only try-lock the shared boundary and keep an older
  one if the lock is busy.

Book changes: rewrote the cascade excerpt and the pdqsort-inside-ska_sort
text; new §15.5.4 (merge buffer) and §15.6.5 (HashedSort integer
partitioning); callouts for `-0.0` and TopN boundary; updated the v1.4.0 caveat
